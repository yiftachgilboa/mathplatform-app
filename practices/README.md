# התנסויות (שלב 2 בשיעור)

כל התנסות היא קובץ HTML אחד: React מ-CDN + JSX שמקומפל בדפדפן (Babel). אפשר לפתוח ולערוך אותו לבד.

## איך מעלים התנסות

1. שמים את קובץ המקור כאן: `practices/<name>.html`.
2. מריצים `npm run build-practices` — יוצר את `public/practices/<name>.html` (בלי Babel, מהיר בטלפון). **לא עורכים את הקובץ ב-public.**
3. בקובץ הקורס (`content/courses/kidodo-g1.json`), בשלב של השיעור:
   `"interactive": { "page": "/practices/<name>.html" }`
4. commit לשני הקבצים (מקור + public) ו-push.

## החיבור לקורס — `public/practices/kidodo-practice.js`

הקורס מציג את ההתנסות **בתוך שלב 2, ב-iframe** (`components/course/PracticeStage.tsx`), עם `?childId=&courseId=&lessonId=`:

- היא נטענת מיד כשנכנסים לשלב 2, ומוצגת מוקטנת: ההתנסות "רואה" מסך בגובה 640px, מוקטן לגודל התיבה. אפשר כבר לשחק בה בקטן.
- כפתור בפינה מגדיל למסך מלא (באייפון: שכבה על כל המסך). ה-✕ של ההתנסות או Esc מחזירים לקטן.
- טעינה מוקדמת: כשהשיעור פתוח, הקורס מוריד ברקע את קובץ ההתנסות ואת הספריות (`PRACTICE_ASSETS` ב-`lib/course/practice.ts` — אם משנים את הספריות בתבנית, מעדכנים גם שם).
- הקול מתחמם בלחיצה שמביאה לשלב 2 (`warmSpeech`), כדי שההקראה הראשונה לא תהיה איטית.
- ההתנסות מעוצבת למסך מלא (`100dvh`) — בתוך ה-iframe זה הגובה של ה-iframe.

בתוך iframe הקריאות `next/exit/complete` לא מנווטות, אלא שולחות לעמוד הקורס `postMessage({ kidodo: 'next' | 'exit' | 'complete' })`. כשפותחים את הקובץ לבד או בעמוד מלא — הן מנווטות כמו קודם.

בקובץ ההתנסות:

```html
<script src="/practices/kidodo-practice.js"></script>
```

| קריאה | מה היא עושה |
|---|---|
| `KidodoPractice.answer(correct)` | שומר תשובה (שלב 2, לא נספר לשליטה) |
| `KidodoPractice.complete(extra)` | מסמן ✓ לשלב 2 (Promise, אף פעם לא נכשל, עד 2.5 שניות) |
| `KidodoPractice.next()` | עובר לשלב 3 (ומקטין אם היה במסך מלא) |
| `KidodoPractice.exit()` | מקטין חזרה לתוך השלב (בעמוד מלא: חוזר לקורס, לשלב 2) |
| `KidodoPractice.embedded` | `true` כשההתנסות בתוך הקורס (iframe) |
| `KidodoPractice.inCourse` | `false` כשפותחים את הקובץ לבד — אז לא נשמר כלום |

## משחק בשלב 3 (תרגול) או 4 (העשרה)

אותו מבנה בדיוק (קובץ מקור כאן ← `npm run build-practices`), אבל בקובץ הקורס:
`"practice": { "gameId": "<name>", "href": "/practices/<name>.html" }`.
הקורס מציג אותו **בתוך השלב, בקטן** (כמו שלב 2, אותו `PracticeStage`, עם כפתור הגדלה), עם `&courseStage=3` (או 4). `kidodo-practice.js` שומר את התשובות ואת ה-✓ לפי השלב הזה, ו-`next` עובר לשלב הבא. תשובות בשלב 3 נספרות לשליטה (90%).

גם משחקי React הישנים (`/games/...`, עם `mathplatform-sdk-v1.js`) מוצגים כך: בתוך ה-iframe ה-SDK לא מנווט — `router.back()` שולח `exit` (או `next` אחרי סוף המשחק), ואחרי `GAME_OVER` הוא שולח `complete` והקורס מרענן את ההתקדמות מהשרת.

- `bridge10.html` — **בונים גשר** (שיעור מעלית, שלב 3): 5 מכשולים ברצף ברוחב 5–10 — מים (תמיד ראשון), ואחריו אש, קוצים, ביצה ומפלצת בסדר אקראי, לכל אחד אנימציה קטנה בלולאה. הקרשים שטוחים, נגררים לכל מקום, כל זוג מתחבר (משחררים קרש על קרש), ותנועת ״סכין״ חותכת קרש בכל יחידה. מעל הבור רק מד מרחק ומספר. כשהגשר מוכן הדמות הולכת במקום והעולם זז שמאלה; הבורות רחוקים זה מזה, כך שהבא לא נראה מראש. לכל קטע אדמה צבע משלו וקישוטים קטנים משלו (עצים, פטריות, קקטוסים, גבישים…), ובאופק דברים רחוקים שזזים לאט יותר. גשר שהונח הופך לגשר דק במבט מהצד (משטח בצבעי הקרשים, עמודים ומעקה), בדיוק בין שתי הקצוות. הדמות בבגדים אדומים בהירים, וקופצת מדי פעם כשהיא מחכה. בלי מסך פתיחה — המשחק מתחיל מיד. למעלה: בפינה השמאלית יציאה, קול ו״לסדר מחדש״ זה מתחת לזה; באמצע תיבה ופס התקדמות; המספר הוא חייזר סגול (לא הדמות של המשחק) עם כפתור רמקול לידו להשתקת הדיבור. הבורות ממולאים עד קו הדשא; ההרים מאחור מוחשכים מעט, השמיים בהירים. הבור תמיד במרכז המסך (הדמות עומדת בקצה שלו וזזה מעט בהליכה). שורה עליונה אחת: חייזר + רמקול + בועה קצרה מימין, תיבה ופס משמאל. אפשר להניח קרשים מתחת לבועה ועד גובה הרצפה. **מפלצת רודפת** (פי 2 מהדמות) מתקרבת משמאל בזמן שבונים ונוהמת מדי פעם: בסבב הראשון יש דקה, ואחר כך 1.2 × זמן הפתרון הקודם (15–120 שניות). היא נכנסת מחוץ למסך ובורחת החוצה כשהגשר מוכן; בהליכה זזות העיניים והגבה (לא הפה). כשהיא קרובה הדמות מסתובבת אליה בלי חיוך. אם קצה המפלצת מגיע לדמות — המסך רועד, הדמות מתפוצצת לחלקיקים בצבעים שלה וחוזרת, אותו בור חוזר עם קרשים אחרים, והמפלצת איטית פי 2. היא עוצרת כשהדף לא נראה (requestAnimationFrame). חיבור מציג רק את החיבור האחרון (כל צד הופך לקוביה אחת), ושני חלקים של אותו קרש שמתחברים חזרה הופכים לקוביה אחת בלי ״2+1״. בסוף הדמות מגיעה לתיבת האוצר שעל האדמה, בלי טקסט — רק יד שמראה ללחוץ; לחיצה ← 3 שניות של מטבעות עפים ← מסך סיום: 3 כוכבים (לפי טעויות — גשר שגוי, חיבור שלא מקרב לפתרון או חורג ממנו, ״לסדר מחדש״, מפלצת שתפסה; 0–1 = 3 כוכבים, 2–4 = 2, יותר = 1) וכפתור חץ אחד. למפלצת שאגת ״וואה״ (צליל קולי עם פורמנטים), עיניים, גבה ולוחות גב בסגנון סטגוזאורוס שזזים אקראית. הדמות מצוירת מעל הקישוטים. בסצנה הראשונה רק שני קרשים. אם הילד לא עושה כלום, יד מראה איך מחברים, וכשיש קרש באורך הנכון — איך גוררים אותו אל הבור; בהמשך, אם הוא שוב מחכה, איך חותכים (החיתוך חייב להתחיל קצת רחוק מהקרש). חיבור קורה גם כשקרש חופף רק משבצת אחת של קרש אחר. מד המרחק בגובה הדשא, והגשר יושב מעט מתחת לרגלי הדמות. קרש באורך הנכון — הדמות יוצאת לדרך מיד. אחרי המכשול הראשון ההודעות מופיעות בבועה בלי הקראה (חוץ מטעויות והסיום), וליד הדמות כפתור השתקת דיבור. כל ניסיון גשר = תשובה. הסאונד כולו מקוד (Web Audio). מבוסס על משחק Construct ישן (`addition10`).

## מה כבר קבוע ב-`decomposition.html` (בסיס לתבנית)

- מסגרת: כותרת (שם + תיבת אוצר עם פס התקדמות + כפתורי חזרה/קול/יציאה), במה, דמות מדברת (קול עברי או כתוביות), מקלדת מספרים.
- 4 סבבים ← כל סבב ממלא את התיבה.
- מסך סיום: רק התיבה בגדול. כל לחיצה פותחת אותה ומעיפה מטבעות (בלי לשנות את הפרס). "המשך" ← `complete()` + `next()`.
- מובייל פירסט: נבדק ב-360px ו-375px, כפתורים ≥ 44px.
