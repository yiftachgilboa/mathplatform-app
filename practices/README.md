# התנסויות (שלב 2 בשיעור)

כל התנסות היא קובץ HTML אחד: React מ-CDN + JSX שמקומפל בדפדפן (Babel). אפשר לפתוח ולערוך אותו לבד.

## איך מעלים התנסות

1. שמים את קובץ המקור כאן: `practices/<name>.html`.
2. מריצים `npm run build-practices` — יוצר את `public/practices/<name>.html` (בלי Babel, מהיר בטלפון). **לא עורכים את הקובץ ב-public.**
3. בקובץ הקורס (`content/courses/kidodo-g1.json`), בשלב של השיעור:
   `"interactive": { "page": "/practices/<name>.html" }`
4. commit לשני הקבצים (מקור + public) ו-push.

## החיבור לקורס — `public/practices/kidodo-practice.js`

הקורס מציג את ההתנסות **בתוך שלב 2, ב-iframe** (`components/course/PracticeStage.tsx`), עם `?childId=&courseId=&lessonId=`:

- היא נטענת מיד כשנכנסים לשלב 2, ומוצגת מוקטנת: ההתנסות "רואה" מסך בגובה 640px, מוקטן לגודל התיבה. אפשר כבר לשחק בה בקטן.
- כפתור בפינה מגדיל למסך מלא (באייפון: שכבה על כל המסך). ה-✕ של ההתנסות או Esc מחזירים לקטן.
- טעינה מוקדמת: כשהשיעור פתוח, הקורס מוריד ברקע את קובץ ההתנסות ואת הספריות (`PRACTICE_ASSETS` ב-`lib/course/practice.ts` — אם משנים את הספריות בתבנית, מעדכנים גם שם).
- הקול מתחמם בלחיצה שמביאה לשלב 2 (`warmSpeech`), כדי שההקראה הראשונה לא תהיה איטית.
- ההתנסות מעוצבת למסך מלא (`100dvh`) — בתוך ה-iframe זה הגובה של ה-iframe.

בתוך iframe הקריאות `next/exit/complete` לא מנווטות, אלא שולחות לעמוד הקורס `postMessage({ kidodo: 'next' | 'exit' | 'complete' })`. כשפותחים את הקובץ לבד או בעמוד מלא — הן מנווטות כמו קודם.

בקובץ ההתנסות:

```html
<script src="/practices/kidodo-practice.js"></script>
```

| קריאה | מה היא עושה |
|---|---|
| `KidodoPractice.answer(correct)` | שומר תשובה (שלב 2, לא נספר לשליטה) |
| `KidodoPractice.complete(extra)` | מסמן ✓ לשלב 2 (Promise, אף פעם לא נכשל, עד 2.5 שניות) |
| `KidodoPractice.next()` | עובר לשלב 3 (ומקטין אם היה במסך מלא) |
| `KidodoPractice.exit()` | מקטין חזרה לתוך השלב (בעמוד מלא: חוזר לקורס, לשלב 2) |
| `KidodoPractice.embedded` | `true` כשההתנסות בתוך הקורס (iframe) |
| `KidodoPractice.inCourse` | `false` כשפותחים את הקובץ לבד — אז לא נשמר כלום |

## משחק בשלב 3 (תרגול) או 4 (העשרה)

אותו מבנה בדיוק (קובץ מקור כאן ← `npm run build-practices`), אבל בקובץ הקורס:
`"practice": { "gameId": "<name>", "href": "/practices/<name>.html" }`.
הקורס פותח אותו בעמוד מלא עם `&courseStage=3` (או 4), ו-`kidodo-practice.js` שומר את התשובות, את ה-✓ ואת `next/exit` לפי השלב הזה. תשובות בשלב 3 נספרות לשליטה (90%).

- `bridge10.html` — **בונים גשר** (שיעור מעלית, שלב 3): מחברים קרשים עד שהם בדיוק ברוחב הנהר (5–10). 5 גשרים ← תיבת אוצר. הקרשים שטוחים, נגררים ונשארים בכל מקום, כל זוג מתחבר (משחררים קרש על קרש), ותנועת ״סכין״ מהירה דרך קרש מחובר מפרקת אותו בחיבור הקרוב. האדמה והנהר בתחתית המסך, מקצה לקצה. כל ניסיון גשר = תשובה. הסאונד כולו מקוד (Web Audio), בלי קבצים. מבוסס על משחק Construct ישן (`addition10`).

## מה כבר קבוע ב-`decomposition.html` (בסיס לתבנית)

- מסגרת: כותרת (שם + תיבת אוצר עם פס התקדמות + כפתורי חזרה/קול/יציאה), במה, דמות מדברת (קול עברי או כתוביות), מקלדת מספרים.
- 4 סבבים ← כל סבב ממלא את התיבה.
- מסך סיום: רק התיבה בגדול. כל לחיצה פותחת אותה ומעיפה מטבעות (בלי לשנות את הפרס). "המשך" ← `complete()` + `next()`.
- מובייל פירסט: נבדק ב-360px ו-375px, כפתורים ≥ 44px.
