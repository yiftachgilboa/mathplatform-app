# התנסויות (שלב 2 בשיעור)

כל התנסות היא קובץ HTML אחד: React מ-CDN + JSX שמקומפל בדפדפן (Babel). אפשר לפתוח ולערוך אותו לבד.

## איך מעלים התנסות

1. שמים את קובץ המקור כאן: `practices/<name>.html`.
2. מריצים `npm run build-practices` — יוצר את `public/practices/<name>.html` (בלי Babel, מהיר בטלפון). **לא עורכים את הקובץ ב-public.**
   - **ארט:** משחק שטוען את ספריית הארט עם `<script src="../art/lowpoly.js"></script>` מקבל אותה מוטמעת (וממוזערת) בקובץ החי — בלי בקשה נוספת. אחרי שינוי ב-`art/lowpoly.js` מריצים שוב את ה-build.
   - **גיבוי:** `bridge10-v1.html` הוא ״בונים גשר״ לפני המעבר לספריית הארט (גם תג git `v-bridge10-before-art`). נפתח לבד ב-`/practices/bridge10-v1.html` להשוואה.
3. בקובץ הקורס (`content/courses/kidodo-g1.json`), בשלב של השיעור:
   `"interactive": { "page": "/practices/<name>.html" }`
4. commit לשני הקבצים (מקור + public) ו-push.

## החיבור לקורס — `public/practices/kidodo-practice.js`

הקורס מציג את ההתנסות **בתוך שלב 2, ב-iframe** (`components/course/PracticeStage.tsx`), עם `?childId=&courseId=&lessonId=`:

- היא נטענת מיד כשנכנסים לשלב 2, ומוצגת מוקטנת: ההתנסות "רואה" מסך בגובה 640px, מוקטן לגודל התיבה. היא קפואה ושקטה עד שלוחצים Play (ראו ״Play ועצירה״), ואז אפשר לשחק בה בקטן.
- כפתור בפינה מגדיל למסך מלא (באייפון: שכבה על כל המסך). ה-✕ של ההתנסות או Esc מחזירים לקטן.
- טעינה מוקדמת: כשהשיעור פתוח, הקורס מוריד ברקע את קובץ ההתנסות ואת הספריות (`PRACTICE_ASSETS` ב-`lib/course/practice.ts` — אם משנים את הספריות בתבנית, מעדכנים גם שם).
- הקול מתחמם בלחיצה שמביאה לשלב 2 (`warmSpeech`), כדי שההקראה הראשונה לא תהיה איטית.
- ההתנסות מעוצבת למסך מלא (`100dvh`) — בתוך ה-iframe זה הגובה של ה-iframe.

בתוך iframe הקריאות `next/exit/complete` לא מנווטות, אלא שולחות לעמוד הקורס `postMessage({ kidodo: 'next' | 'exit' | 'complete' })`. כשפותחים את הקובץ לבד או בעמוד מלא — הן מנווטות כמו קודם.

בקובץ ההתנסות:

```html
<script src="/practices/kidodo-practice.js"></script>
```

| קריאה | מה היא עושה |
|---|---|
| `KidodoPractice.answer(correct)` | שומר תשובה (שלב 2, לא נספר לשליטה) |
| `KidodoPractice.complete(extra)` | מסמן ✓ לשלב 2 (Promise, אף פעם לא נכשל, עד 2.5 שניות) |
| `KidodoPractice.next()` | עובר לשלב 3 (ומקטין אם היה במסך מלא) |
| `KidodoPractice.exit()` | מקטין חזרה לתוך השלב (בעמוד מלא: חוזר לקורס, לשלב 2) |
| `KidodoPractice.look()` / `onLook(fn)` | מה הדמות של הילד לובשת, ועדכון באמצע משחק. **הדמות במשחק מצוירת רק דרך `LP.hero(look, {pose, t, rot})`** (לא `make.buddy`) |
| `KidodoPractice.reward()` | כמה מטבעות מקבלים על תרגול (להצגה במשחק). `complete()` נקרא פעם אחת בכל סיום משחק |
| `KidodoPractice.onResume(fn)` | הילד חזר מעצירה ושום משפט לא נקטע: כאן אומרים שוב את ההוראה |
| `KidodoPractice.embedded` | `true` כשההתנסות בתוך הקורס (iframe) |
| `KidodoPractice.inCourse` | `false` כשפותחים את הקובץ לבד — אז לא נשמר כלום |

## Play ועצירה

בתוך הקורס כל משחק נטען **קפוא ושקט**, וכפתור Play מעליו (`PracticeStage`) מתחיל קול, זמן ותנועה. פתיחת החנות, מסך החגיגה והסתרת הדף עוצרים אותו, וחוזרים שוב ב-Play; משפט שנקטע נאמר מההתחלה. ביציאה מהשלב ההקראה מושתקת.

המנגנון (`KidodoPause`, בתוך `kidodo-practice.js`) עוצר את השעון של הדף: `setTimeout`, `setInterval`, `requestAnimationFrame`, `performance.now`, אנימציות CSS/WAAPI, Web Audio והקראה. משחק חדש מקבל את זה לבד, בתנאי ש:
- `kidodo-practice.js` נטען **אחרי React ולפני המשחק**;
- זמן נמדד ב-`performance.now()` (לא `Date.now()`);
- המשחק מתחיל לבד (`start()` בטעינה) כשהוא בתוך הקורס — מסך ה-Play הוא מסך הפתיחה.

משחק שנפתח לבד (לא בקורס) רץ מיד, ונעצר רק כשהדף מוסתר. משחקי SDK ישנים נטענים רק ב-Play, והקורס מזריק להם את אותו קובץ (`data-run`).

## משחק בשלב 3 (תרגול) או 4 (העשרה)

אותו מבנה בדיוק (קובץ מקור כאן ← `npm run build-practices`), אבל בקובץ הקורס:
`"practice": { "gameId": "<name>", "href": "/practices/<name>.html" }`.
הקורס מציג אותו **בתוך השלב, בקטן** (כמו שלב 2, אותו `PracticeStage`, עם כפתור הגדלה), עם `&courseStage=3` (או 4). `kidodo-practice.js` שומר את התשובות ואת ה-✓ לפי השלב הזה, ו-`next` עובר לשלב הבא. תשובות בשלב 3 נספרות לשליטה (90%).

גם משחקי React הישנים (`/games/...`, עם `mathplatform-sdk-v1.js`) מוצגים כך: בתוך ה-iframe ה-SDK לא מנווט — `router.back()` שולח `exit` (או `next` אחרי סוף המשחק), ואחרי `GAME_OVER` הוא שולח `complete` והקורס מרענן את ההתקדמות מהשרת.

- `bridge10.html` — **בונים גשר** (שיעור מעלית, שלב 3): 5 מכשולים ברצף ברוחב 5–10 — מים (תמיד ראשון), ואחריו אש, קוצים, ביצה ומפלצת בסדר אקראי, לכל אחד אנימציה קטנה בלולאה. הקרשים שטוחים, נגררים לכל מקום, כל זוג מתחבר (משחררים קרש על קרש), ותנועת ״סכין״ חותכת קרש בכל יחידה. מעל הבור רק מד מרחק ומספר. כשהגשר מוכן הדמות הולכת במקום והעולם זז שמאלה; הבורות רחוקים זה מזה, כך שהבא לא נראה מראש. לכל קטע אדמה צבע משלו וקישוטים קטנים משלו (עצים, פטריות, קקטוסים, גבישים…), ובאופק דברים רחוקים שזזים לאט יותר. גשר שהונח הופך לגשר דק במבט מהצד (משטח בצבעי הקרשים, עמודים ומעקה), בדיוק בין שתי הקצוות. הדמות בבגדים אדומים בהירים, וקופצת מדי פעם כשהיא מחכה. בלי מסך פתיחה — המשחק מתחיל מיד. למעלה: בפינה השמאלית יציאה, קול ו״לסדר מחדש״ זה מתחת לזה; באמצע תיבה ופס התקדמות; המספר הוא חייזר סגול (לא הדמות של המשחק) עם כפתור רמקול לידו להשתקת הדיבור. הבורות ממולאים עד קו הדשא; ההרים מאחור מוחשכים מעט, השמיים בהירים. הבור תמיד במרכז המסך (הדמות עומדת בקצה שלו וזזה מעט בהליכה). שורה עליונה אחת: חייזר + רמקול + בועה קצרה מימין, תיבה ופס משמאל. אפשר להניח קרשים מתחת לבועה ועד גובה הרצפה. **מפלצת רודפת** (פי 2 מהדמות) מתקרבת משמאל בזמן שבונים ונוהמת מדי פעם: בסבב הראשון יש דקה, ואחר כך 1.2 × זמן הפתרון הקודם (15–120 שניות). היא נכנסת מחוץ למסך ובורחת החוצה כשהגשר מוכן; בהליכה זזות העיניים והגבה (לא הפה). כשהיא קרובה הדמות מסתובבת אליה בלי חיוך. אם קצה המפלצת מגיע לדמות — המסך רועד, הדמות מתפוצצת לחלקיקים בצבעים שלה וחוזרת, אותו בור חוזר עם קרשים אחרים, והמפלצת איטית פי 2. היא עוצרת כשהדף לא נראה (requestAnimationFrame). חיבור מציג רק את החיבור האחרון (כל צד הופך לקוביה אחת), ושני חלקים של אותו קרש שמתחברים חזרה הופכים לקוביה אחת בלי ״2+1״. בסוף הדמות מגיעה לתיבת האוצר שעל האדמה, בלי טקסט — רק יד שמראה ללחוץ; לחיצה ← 3 שניות של מטבעות עפים ← מסך סיום: 3 כוכבים (לפי טעויות — גשר שגוי, חיבור שלא מקרב לפתרון או חורג ממנו, ״לסדר מחדש״, מפלצת שתפסה; 0–1 = 3 כוכבים, 2–4 = 2, יותר = 1) וכפתור חץ אחד. למפלצת שאגת ״וואה״ (צליל קולי עם פורמנטים), עיניים, גבה ולוחות גב בסגנון סטגוזאורוס שזזים אקראית. הקישוטים מצוירים בשכבה קדמית, לפני הדמות והמפלצת (עומק בהליכה). כשהמפלצת קרובה העין שלה נעולה על הדמות, והדמות מרימה ידיים לכיוונה ורועדת. מונה מטבעות ליד הפס: 10 לכל מטבע שנאסף; המטבעות שעפים מהתיבה הם אותם מטבעות של המשחק. במסך הסיום: כוכבים, סך המטבעות, חץ להמשך, ומתחתיו כפתור להתחיל מחדש. הטוטוריאל מראה רק מה שהילד עוד לא עשה (חיבור, גרירת גשר, חיתוך, לחיצה על התיבה) ונזכר במכשיר לכל ילד (`localStorage`, `kidodo-bridge-learned-<childId>`); היד לא מופיעה בזמן גרירה או חיתוך. העננים זזים, והקרשים אחידים בלי קו על כל יחידה. בסצנה הראשונה רק שני קרשים. אם הילד לא עושה כלום, יד מראה איך מחברים, וכשיש קרש באורך הנכון — איך גוררים אותו אל הבור; בהמשך, אם הוא שוב מחכה, איך חותכים (החיתוך חייב להתחיל קצת רחוק מהקרש). חיבור קורה גם כשקרש חופף רק משבצת אחת של קרש אחר. מד המרחק בגובה הדשא, והגשר יושב מעט מתחת לרגלי הדמות. קרש באורך הנכון — הדמות יוצאת לדרך מיד. אחרי המכשול הראשון ההודעות מופיעות בבועה בלי הקראה (חוץ מטעויות והסיום), וליד הדמות כפתור השתקת דיבור. כל ניסיון גשר = תשובה. הסאונד כולו מקוד (Web Audio). מבוסס על משחק Construct ישן (`addition10`).

- `climb.html` — **מטפסים לפני המים** (שיעור מדרגות, שלב 3), לפי האפיון ״מפתח המדרגות״ 0.1: מגדל של איים מרחפים מהספרייה (אחו ← סלעים ← קרח) עד קומה 15 עם התיבה. רק הקומות שהשחקן הגיע אליהן בנויות. בכל שאלה: ״+k״ בתכלת ליד הקומה הנוכחית (רק המספר שלה מוצג), התרגיל `N + k = ?` שלוש קומות מעל ועולה עם הדמות, ושלוש תשובות עוקבות. נכון ← הקומות נבנות אחת־אחת והדמות קופצת (תו עולה בכל קומה); שגוי ← מחליקה 3 קומות (בקומה 1 — אותו תרגיל שוב). מים עולים עם זמן יעד T (60 שניות, ואחרי התשובה הנכונה הראשונה 1.5× זמן התשובה; כל מגע +30%), מחושבים מחדש בכל שאלה. ההוראה המילולית בבועה רק בשני הטיפוסים הראשונים; הקראה כבויה כברירת מחדל (כפתור הבועה). לרוחב — התשובות בעמודה מימין. מקלדת: מקלידים את המספר. כוכבים לפי טעויות + מגעי מים (0–1 = 3, 2–4 = 2). הפרמטרים בראש הקובץ (`CFG`).

- `elevator.html` — **הבלש והמעלית** (שיעור מעלית, שלב 2), לפי האפיון של יפתח ״מעלית למספר הגדול ומדרגות לקטן״. סיפור: מישהו מהספרייה (שועל, ארנב, דוב…) מסתתר בקומה ״7 ועוד 2״; 5 תיקים. בכל תיק: לוחצים על המספר הגדול ← מעלית לקומה שלו ← ״עולים קומה״ כמספר הקטן (+1 בכל לחיצה) ← ״באיזו קומה הגענו?״ מתוך 3 ← מוצאים את מי שהסתתר, חותמת ״התיק נפתר!״, והעיר מקבלת עוד צבע (מתחילה בשחור־לבן). בחצי מהתיקים הקטן כתוב ראשון. מהתיק השלישי (`HIDE_FROM`) מספרי הקומות מעל המספר הגדול נעלמים והילד סופר לבד; טעות בתשובה מחזירה אותם. טעות = רעידה, באזז ורמז; כוכבים לפי טעויות. העוזר הוא הדמות של הילד (`LP.hero`), והוא גם מי שנוסע במעלית. שני כפתורי קול: אפקטים+דיבור, ומוזיקה (בס מהלך בקוד). מקלדת: מקלידים את המספר, חץ למעלה = קומה. הפרמטרים ב-`CFG`.

## מה כבר קבוע ב-`decomposition.html` (בסיס לתבנית)

- מסגרת: כותרת (שם + תיבת אוצר עם פס התקדמות + כפתורי חזרה/קול/יציאה), במה, דמות מדברת (קול עברי או כתוביות), מקלדת מספרים.
- 4 סבבים ← כל סבב ממלא את התיבה.
- מסך סיום: רק התיבה בגדול. כל לחיצה פותחת אותה ומעיפה מטבעות (בלי לשנות את הפרס). "המשך" ← `complete()` + `next()`.
- מובייל פירסט: נבדק ב-360px ו-375px, כפתורים ≥ 44px.

## כפתור ההגדלה בפינה (`claimCorner`)

משחק שמשאיר ריק את המקום של כפתור ה-✕ בפינה השמאלית־העליונה (44px, `left:10px; top:10px`) קורא ל-`KidodoPractice.claimCorner()` כשהוא בתוך הקורס (`KidodoPractice.embedded`). אז הקורס שם שם כפתור עגול בהיר: הגדלה כשהמשחק קטן, חזרה לגודל רגיל במסך מלא. בתוך הקורס אין ✕ (כשהמשחק נפתח לבד — יש). משחק שלא קורא לזה — נשאר הכפתור הכחול הישן למטה. ראשון: ״בונים גשר״.
